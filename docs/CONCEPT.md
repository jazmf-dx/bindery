# Bindery で何を作るか

**状態**：作り始めた（2026-11-22）。jazmf-dx/desktop-platform の `docs/file-app.md` で検討したものを、ここに移した（desktop-platform からは消した）。

**結論**：PDF・オフィス文書・テキストを、**元の場所に置いたまま** タグ・仮想フォルダ・メモで横断的に整理するアプリ。
ファイルを取り込まず、書き換えず、動かさない。強みは「散らばったファイルを、置き場所を変えずにまとめて見つけられる」こと。

## 経緯

- Stockroom（hamirilo/stockroom）は v0.46.0 で扱う種類を画像と動画だけに絞った。強みの「見た目で探して選ぶ」が活きない種類を外した（stockroom の `docs/FILE_APP.md`）
- 外したのは、ファイル（PDF・オフィス文書）、テキスト（Markdown・テキスト・CSV）、ブックマーク（URL）。その受け皿として検討する
- フォントを別アプリ（Typecase）に分けた前例がある（stockroom の `docs/FONT_APP.md`）

## 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| 強みの軸 | **置き場所の整理**。中身での検索やプレビューは補助 | 「見て選ぶ」が活きない種類では、見つける手がかりは名前・場所・付けた情報になる |
| 扱う種類 | PDF・オフィス文書・テキスト（Markdown・テキスト・CSV） | |
| ブックマーク | **扱わない** | ブラウザとの連携と通信が要る（リンク切れの確認・更新・中身の保存）。デスクトップアプリの「URL を取りに行かない」原則とぶつかる。要るなら Web アプリとして別に検討する |
| ファイルの持ち方 | **元の場所のまま参照する**。ライブラリへの取り込み（複製）はしない | 置き場所（共有ドライブ・OneDrive など）は業務の都合で決まっていて、アプリ側に移せない。複製すると元と食い違う |
| 対象の範囲 | **登録したフォルダの配下** だけ。外のファイルを 1 つずつは足さず、入っているフォルダを直下だけで登録して代える（2026-11-26 に見直した。下の「整理を手早くする」） | 登録フォルダは全体を把握しやすく、移動も追いやすい。個別の追加は照合・行方不明・最近の変更に別の道が要り、親フォルダの登録で「この 1 つだけ」にほぼ足りる |
| 移動・改名の追跡 | **開いたとき（起動・再読み込み）に照合する**。常時の監視はしない | 共有ドライブでは監視の通知が届かないことがある。照合の順は下の「照合」 |
| 実ファイルの操作 | **しない**。アプリが書くのは自分のデータ（タグ・仮想フォルダ・メモ）だけ | 元のファイルを壊さない・動かさないことを保証できる。移動・改名は Finder / エクスプローラーで |
| 全文検索 | **後回し**。最初は名前・場所・タグ・メモで探す | 整理の仕組みを先に固める。入れるときは Stockroom の文字コード判定（Shift_JIS）を使う |
| Feedability の記事とリンク | **受けない** | ブックマークを扱わないのと合わせる。記事は Feedability 側で `.md` に書き出せば、普通のテキストとして扱える。待ち受けポートも増やさない |
| Stockroom から外したコード | **部品だけ持ってくる**。プレビュー（Quick Look・Windows.Data.Pdf・Office の PDF 変換）と、テキストの文字コード判定・読み書き | ライブラリ・取り込みの作り（複製が前提）は合わないので、新しく考える |
| 土台 | desktop-platform の Standard に従い、共通の部品（desktop-base）を使う。無ければ `playbook/new-tool.md` の「desktop-base がまだ無いとき」 | stockroom の `docs/FONT_APP.md` の「方針」4 |
| 名前 | **Bindery**（製本所。ばらばらの紙を綴じて 1 冊にまとめる場所）。`identifier` は `com.local.bindery` | 散らばったファイルを動かさずにまとめる役目に合う。Typecase（活字ケース）と同じ印刷・製本の言葉でそろう |
| リポジトリ | `jazmf-dx/bindery` | 社内向けとして最初から組織に置く |
| データの置き場 | **`app_data_dir()` の SQLite に 1 つ**（タグ・仮想フォルダ・メモ・登録フォルダ・照合用の情報） | 選ぶ手間が無い。整理はその端末のものになる（ほかの端末へは書き出し・読み込みで移す）。共有ドライブや元のファイルに書かない決定とも合う |
| 一覧 | **リストだけ**（名前・場所・種類・更新日・タグの列）。グリッドと表示の切り替えは持たない | 「見て選ぶ」は強みではない。切り替えが無ければ操作の位置も変わらない（UI Standard「レイアウトの安定」） |
| プレビュー | **右の詳細パネルに小さく出し、スペースで大きく開く**。詳細パネルにはタグ・メモ・場所も出す | 一覧と並べて確かめられ、必要なときだけ大きく見られる |
| サイドバー | 上から **仮想フォルダ → タグ → 登録フォルダ**。「最近の変更」「未整理」（タグも仮想フォルダも無い）「行方不明」は特別な項目として一番上 | 整理した結果を上に、元の場所を下に置き、「置き場所を変えずにまとめる」強みを前に出す |
| この文書の置き場 | このリポジトリの `docs/CONCEPT.md`（はじめは desktop-platform の `docs/file-app.md` に書いた） | |

## Finder やエディタで足りないか

作らない結論もありうるので、足りない点を挙げておく。下のどれも要らないなら作らない。

| 欲しいこと | Finder / エクスプローラーでは |
|---|---|
| フォルダをまたいでまとめる（「案件 A」の資料が共有ドライブと手元に散らばっている） | ショートカット・エイリアスを手で作るしかない。元が動くと切れる |
| タグ | macOS の Finder タグはあるが、Windows には無い。共有ドライブ上ではほかの人と混ざる・消えることがある |
| メモ（このファイルは何か、どの版が最新か） | 付けられない（ファイル名に書き込むしかない） |
| 種類をまたいだ一覧（PDF・Excel・CSV を一緒に、タグで絞る） | 検索条件の保存はあるが、OS ごとに違い、タグとは組み合わせにくい |
| 中身の確認 | Quick Look（macOS）はある。Windows のプレビューウィンドウは種類によって出ない |

アプリの情報（タグ・メモ）は自分の端末のアプリのデータに持ち、元のファイルにも共有ドライブにも書かない。

## 照合

起動時と再読み込みのとき、覚えているファイルを次の順で探す。

1. 覚えているパスにある → そのまま
2. 無い → 登録フォルダの中から、ファイル ID（macOS の inode・Windows の File ID）が同じものを探す
3. それも無い → 大きさとハッシュが同じものを探す
4. 見つからない → **行方不明** として残す（タグ・メモは消さない）。手でつなぎ直すか、外せる

登録フォルダに新しく増えたファイルは、タグ無しの項目として一覧に出る。

## 登録フォルダと一覧（2026-11-22）

| 論点 | 決定 |
|---|---|
| 読む深さ | 下の階層まで全部（2026-11-25 から登録するときに選べる。下の「登録のしかたと中のフォルダ」）。隠しファイル（`.` で始まる名前）・Office の一時ファイル（`~$`）・`node_modules`・`$RECYCLE.BIN`・`System Volume Information` は飛ばす |
| 扱う拡張子 | PDF（`pdf`）、Word（`doc` `docx` `rtf` `odt`）、Excel（`xls` `xlsx` `xlsm` `ods`）、PowerPoint（`ppt` `pptx` `odp`）、テキスト（`txt` `md` `markdown` `csv` `tsv`）。`src-tauri/src/scan.rs` の `kind_of` |
| ハッシュ | **後ろで少しずつ** 計算する。登録したらまず名前・大きさ・更新日時で一覧に出し、ハッシュは 1 件ずつ裏で計算して保存する。大きさか更新日時が変わったら捨てて計算し直す。読めなかったファイルは空の印を付け、何度も読まない |
| 照合のしかた | 同じパス → ファイル ID（ほかの登録フォルダへ移ったものも探す）→ ハッシュ（計算できたときに、大きさとハッシュが同じ行方不明の行へつなぎ直す）。つなぎ直したときは、行方不明だった行の id を残す（あとで付くタグ・メモはそちらに付いているため） |
| 見えないフォルダ | 登録フォルダそのものが見えない（ドライブ・共有がつながっていない）ときは、そのフォルダは読まずに前のままにする。読むと中が全部行方不明になってしまうため |
| 入れ子 | すでに登録したフォルダの中や、それを含むフォルダは登録できない（同じファイルが 2 つのフォルダに入るため）。直下だけ読むフォルダとは重ならないので、その中や、それを直下だけで含むフォルダは登録できる（2026-11-25） |
| 登録を外す | 作った。サイドバーの行を指したときに出る ✕ で外す。アプリのデータの中のそのフォルダとファイルの行を消す。元のファイルには触らない。今は確認を出さない（タグ・メモが付くようになったら、消える前に確認を出す） |
| 読むとき | 起動したとき、フォルダを登録したとき、［読み直す］（⌘R / Ctrl+R）のとき |
| 一覧 | 名前の順。「すべてのファイル」などでは場所を「登録フォルダ名 › 中のフォルダ」で出す。登録フォルダを選んだときは中のフォルダだけ（2026-11-25 から、登録フォルダ・中のフォルダを選ぶと直接入っているものだけを出す） |
| 未整理 | タグも仮想フォルダも付いていないもの |

行方不明のつなぎ直し・外す操作は 2026-11-25 に作った（下の「探す・最近の変更・メモ・行方不明」）。フォルダの外のファイルを 1 つずつ足すことはしない（上の「対象の範囲」）。

## タグ・仮想フォルダ・Quick Look（2026-11-23）

| 論点 | 決定 |
|---|---|
| Quick Look | **段階を分ける**。今回は OS の Quick Look を開く（スペース、詳細パネルの［Quick Look］）。macOS は `qlmanage -p` で Quick Look のウィンドウを出し、もう一度押すと閉じる。Windows は OS に同じものが無いので既定のアプリで開く。アプリの画面には元のファイルを出さないので CSP は変えない |
| 小さなプレビュー | あとで。詳細パネルに出すには、元のファイルを画面に渡すための CSP・アセットの許可を広げる必要があり、その判断と一緒に決める |
| Finder と同じパネル | `qlmanage` は macOS の Quick Look の道具で、Finder のパネル（QLPreviewPanel）とは別のウィンドウになる。実機で使い勝手を確かめ、足りなければパネルを直接使う作りを検討する |
| 仮想フォルダ | **入れ子あり・1 つのファイルを複数に入れられる**。仮想フォルダを開くと、直接入っているものだけが出る（下の仮想フォルダの中身は含めない。Finder と同じ）。消すと下の仮想フォルダも消える。中のファイルはそのまま |
| タグ | 名前の大文字・小文字は区別しない。名前を変えて別のタグと同じになったら、1 つにまとめる |
| 付け方 | **詳細パネル**（タグは打ち込んで Enter。候補が出る。仮想フォルダは一覧から選ぶ）と、**サイドバーへのドラッグ**（一覧の行を仮想フォルダ・タグへ落とす）。外すのは詳細パネルのチップの ✕ |
| 複数選択 | ⌘/Ctrl クリックで足す・外す、Shift クリックと Shift+矢印で範囲、⌘A / Ctrl+A ですべて。複数のときは詳細パネルでまとめて付け外しする。一部にだけ付いているものは点線のチップで出し、押すと全部に付く |
| 開く操作 | 既定のアプリで開く（ダブルクリック・Enter・⌘↓）、Finder / エクスプローラーで表示（⌘⇧R / Ctrl+Shift+R）、パスをコピー（⌘⌥C / Ctrl+Alt+C） |
| 行方不明のファイル | タグ・仮想フォルダの一覧には出す（付けた情報は残っているので）。行は薄く出し、開く操作は押せない |
| 消すときの確認 | ファイルが付いているタグ・中身のある仮想フォルダを消すとき、タグ・仮想フォルダが付いたファイルを含む登録フォルダを外すときは、確かめてから消す |
| つなぎ直し | ハッシュでつなぎ直すとき、新しい行に付けたタグ・仮想フォルダも、残す行（行方不明だった行）へ移す |

## 登録のしかたと中のフォルダ（2026-11-25）

強みは「Finder / エクスプローラーの外側で、タグ・仮想フォルダで横断的に整理して探せる」こと。元の階層はそのまま見せ、その上に整理を重ねる。

| 論点 | 決定 | 理由 |
|---|---|---|
| ドラッグ＆ドロップ | Finder / エクスプローラーからウィンドウへ **フォルダを落とすと登録** する。重ねているあいだは「落とすと登録する」と出す | ［フォルダを登録…］のダイアログより手早い |
| ファイルを落としたとき | ファイルそのものは登録しない。入っているフォルダが登録済みなら、そこを開いてファイルを選ぶ。まだなら、入っているフォルダを **直下だけ** で登録してよいか聞き、登録してファイルを選ぶ（2026-11-26）。フォルダと混ぜて落としたときは、フォルダだけ登録する | ファイルを 1 つずつ足すことはしない（上の「対象の範囲」） |
| サブフォルダ | **登録するときに選ぶ**（［サブフォルダも含める］［このフォルダだけ］［やめる］）。サブフォルダが無ければ聞かない。まとめて落としたときは 1 回だけ聞く。ドラッグでもダイアログでも同じ。登録フォルダごとに覚え、読み直すときもそれに従う。前から登録してあるフォルダは「含める」 | 使う人が範囲を決められるように |
| 選び直し | 今は、登録を外して登録し直す | 変える操作は、要るとわかってから足す |
| 中のフォルダ | **サイドバーの登録フォルダの下に、元の階層のまま木で出す**（▸ で開け閉め。はじめは閉じている）。出すのは、扱うファイルが下のどこかにあるフォルダだけ | 元の置き場所のまま見られるように。空のフォルダまで出すと木が長くなる |
| 選んだときの一覧 | 登録フォルダ・中のフォルダを選ぶと、**直接入っているファイルだけ** を出す（Finder・仮想フォルダと同じ）。件数も直接入っている数 | 階層をそのまま見せるため。下の階層までまとめて見るときは「すべてのファイル」やタグ・仮想フォルダで |

メモは 2026-11-25、仮想フォルダのドラッグでの移動と右クリックのメニューは 2026-11-26 に作った。

## 探す・最近の変更・メモ・行方不明（2026-11-25）

[ROADMAP.md](ROADMAP.md) の Now（0.2.0）。

| 論点 | 決定 | 理由 |
|---|---|---|
| 絞り込み | 一覧の上の欄（⌘F / Ctrl+F）。**今の場所の中で絞る**。空白で区切った言葉が全部、名前・場所（パス）・タグの名前・メモのどこかに入っているもの。全角・半角、大文字・小文字は区別しない。場所を変えても文字は残す。Esc で空にする | タグ・仮想フォルダを選んだまま絞れる。全体から探すときは「すべてのファイル」で |
| 並べ替え | 列の見出し（名前・場所・種類・更新日）を押す。もう一度押すと逆。日付は新しい順から。**全体で 1 つ覚える**（この端末の画面の設定。データベースには入れない）。同じものどうしは名前の順 | 場所を変えるたびに並びが変わらないように |
| 最近の変更 | サイドバーの特別な項目。**アプリが変化に気付いた日時** を記録し、7 日以内のものを出す。対象は **中身が変わったもの**（大きさか更新日時が変わった）と **新しく増えたもの**。動かした・名前を変えただけのもの、行方不明になったものは出さない。既読は持たない | ファイルの更新日時だけだと、古い更新日時のままコピーで増えたものが漏れ、登録した直後にも出てしまう |
| 最近の変更の細部 | 登録して最初の読み込みで見つけたものは「増えた」に入れない（登録フォルダに「1 度読んだか」を持つ）。気付くのは起動時と［読み直す］だけ（常時の監視はしない。上の「移動・改名の追跡」）。期間の 7 日は設定画面ができるまで固定（`db.rs` の `RECENT_DAYS`） | |
| 最近の変更の見せ方 | 既定は気付いた日の新しい順（開くたびに戻す。列を押せば変えられる）。この一覧でだけ、日付の列を「気付いた日」にし、「新規」「更新」の印を付ける | ほかの一覧の列は変えない（UI Standard「レイアウトの安定」） |
| メモ | 詳細パネルに複数行の欄。**1 件を選んだときだけ** 書ける。欄を離れたとき（ほかのファイルを選んだときも）に保存する。そのまま表示（Markdown にしない）。一覧では名前の横に印だけ出す。上限 10,000 文字 | 一覧の列を増やさない。Markdown の表示は依存が増える |
| メモとつなぎ直し | 照合でつなぎ直すとき、残す行にメモが無ければ新しい行のメモを写す。登録を外すときの確認は、メモが付いたものも数える | |
| 行方不明のつなぎ直し | 詳細パネルの［つなぎ直す…］で、OS のダイアログから今の場所のファイルを選ぶ。選べるのは **登録フォルダの中で、読み込みで見つかる場所のファイルだけ**（扱う種類で、隠しフォルダなどの中でないもの。サブフォルダを読まないフォルダでは直下だけ） | 外のファイルを選ぶと、次の読み込みでまた行方不明になる |
| つなぎ直したとき | そのファイルの行がもうあれば（読み込みで新しく見つけていれば）、付けたタグ・仮想フォルダ・メモを引き継いで 1 つにまとめる。残すのは行方不明だった行の id。中身が同じとは限らないのでハッシュは計算し直す | |
| 記録を外す | 行方不明のファイルだけ外せる（複数まとめて）。付けたタグ・仮想フォルダ・メモも消えるので、いつも確かめてから外す。元のファイルには触らない | 行方不明でないものを外しても、次の読み込みでまた出てくるだけ |

## 整理を手早くする（2026-11-26）

[ROADMAP.md](ROADMAP.md) の Next（0.3.0）。

| 論点 | 決定 | 理由 |
|---|---|---|
| 条件の組み合わせ | **一覧の上に条件の行** を置く。タグ（複数選ぶと **すべて付いているもの**）・種類（1 つ）・更新日（今日／7 日／30 日／1 年以内。ファイルの更新日時で）。今の場所の中で絞り、絞り込みの文字とも重ねられる。場所を変えても残す。条件が無いときも行は出す | 置き場を 1 つにまとめる。条件を足しても一覧の位置が動かないように（UI Standard「レイアウトの安定」） |
| 右クリックのメニュー | **OS のメニュー**（Tauri のメニュー。メニューバーと同じ部品）。一覧の行：開く・Quick Look・場所を表示・パスをコピー、タグを付ける・仮想フォルダに入れる（下の階層に一覧）、今のタグ・仮想フォルダから外す、行方不明ならつなぎ直す・記録を外す。選んでいない行を右クリックしたら、その行を選んでから出す。サイドバー：仮想フォルダ（中に作る・名前を変える・一番上へ移す・消す）、タグ（名前を変える・消す）、登録フォルダ・中のフォルダ（Finder / エクスプローラーで表示・読み直す・登録を外す） | 見た目も操作も OS と同じ。ブラウザ（モック）では出ない |
| 仮想フォルダの移動 | サイドバーの行をドラッグして、別の仮想フォルダへ落とすとその下へ、「仮想フォルダ」の見出しへ落とすと一番上へ。自分の下へは移せない | |
| 外のファイル | 上の「対象の範囲」「ファイルを落としたとき」。ROADMAP では Later に移した | |

## 詰めること

- updater の鍵：今は一時的な鍵の公開鍵が入っている（`decisions/project-context.md`）。本番の配布の前に替える
- 画面の細部：リストの列の選び方・並び替え、仮想フォルダの入れ子、タグの付け方（複数選択でまとめて）
- 書き出し・読み込みの形（ほかの端末へ整理を移すとき。パスが違う端末での照合）
- 照合の重さ：登録フォルダが大きい・共有ドライブが遅いときの読み方（差分だけ・後ろで読む）
- 開く操作：既定のアプリで開く、Finder / エクスプローラーで表示、パスをコピー。テキストの編集は外のエディタに任せる（アプリ内で編集しない。「エディタになる」懸念への答え）
- プレビュー：Stockroom の部品をどこまで持ってくるか（Office の PDF 変換は Office が要る）
- 全文検索を入れる時期と範囲
- 社内版（jazmf-dx）で使うか
